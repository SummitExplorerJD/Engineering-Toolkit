# Documentation Conventions

- Write technical documentation and ADRs in English.
- Use requirement identifiers (`FR-###`, `NFR-###`) for normative product behavior.
- Use RFC 2119-style terms only when the statement is intentionally normative.
- Link to the owning document instead of copying detailed content.
- Mark proposals, accepted decisions, observed facts, and unresolved questions distinctly.
- Never describe planned validation as completed evidence.
- Include dates as ISO 8601 calendar dates when a decision needs a date.
- Use relative repository links in Markdown.
- Keep ADRs immutable in meaning after acceptance; supersede them with a new ADR.
- Do not store credentials, private user data, access tokens, or secret-bearing command output.
