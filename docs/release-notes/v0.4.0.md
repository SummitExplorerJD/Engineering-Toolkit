# Engineering Toolkit `v0.4.0`

**Status:** Prepared for stable qualification; not published.

`v0.4.0` adds token-efficient, bounded retrieval over explicitly selected
workspace sources and expands the read-only stdio MCP surface. Canonical files
remain authoritative; SQLite remains an optional, replaceable projection.

## Added

- Explicit context source roots with mandatory and user-configured exclusions,
  binary rejection, deterministic non-overlapping chunks, and bounded file
  eligibility.
- Replaceable SQLite v2 source, chunk, and FTS5 indexes with atomic full
  rebuild and deterministic projection fingerprints.
- Read-only context commands for rebuild, freshness status, source inventory,
  bounded search, and exact indexed-chunk retrieval.
- MCP tools `context_status`, `context_sources`, `context_read`, and
  `workspace_tree`, plus expanded bounded behavior for `context_search`.
- Compact MCP responses that keep structured data authoritative without
  duplicating it into text, while retaining an explicit text-compatibility
  mode.
- Six-platform synthetic release qualification for context freshness,
  exclusions, bounded retrieval, stale refusal, tree synthesis, strict inputs,
  CLI/MCP equivalence, and the exact twelve-tool inventory.

## Token-efficient retrieval

The intended agent flow is staged: inspect freshness and sources, run a bounded
search, then retrieve only an exact indexed chunk when needed. Default commands
do not return a complete repository tree or full source files.

A sanitized local real-project pilot observed 264 eligible sources, 474 chunks,
33 exclusions, and all twelve MCP tools. Three staged-retrieval comparisons
reduced returned bytes by 83.58%, 90.83%, and 87.10% against declared bounded
full-file baselines. These are byte comparisons, not provider token-count
claims.

## Safety and compatibility

- Mandatory exclusions protect Git metadata, Engineering Toolkit operational
  state, common secret paths, dependency trees, and generated output before
  indexing.
- User exclusions are additive and cannot weaken mandatory exclusions.
- Search and read operations fail closed when the projection is missing,
  unsupported, or stale.
- Indexed reads require an exact indexed path and chunk identity; they do not
  provide an arbitrary filesystem-read capability.
- Workspace-tree results are synthesized from the bounded projection and do
  not walk excluded filesystem content at request time.
- MCP remains read-only and stdio-only. It exposes no mutation, approval,
  recovery, provider-runtime, model, resource, prompt, subscription, or remote
  transport capability.
- No new dependency, remote service, tokenizer, model, or automatic index
  rebuild is introduced.

## Upgrade notes

- Existing `engkit.config/v1alpha1` files remain valid. Context source roots and
  exclusions are optional additive configuration.
- Existing SQLite projections are disposable. Run an explicit context rebuild
  to create the v2 projection from canonical workspace files.
- Existing local-intelligence behavior and the bounded Ollama allowlist are
  unchanged. This release makes no new model-compatibility claim.
- Existing installations can use `install.ps1` or `install.sh` with explicit
  upgrade mode after the stable release is published.
- The source and release toolchain require Go 1.27.3. Release binaries are
  built with CGO disabled.

## Known limitations

- Windows executables are not Authenticode-signed.
- macOS executables are not signed or notarized.
- Production TUF activation, automatic updates, self-replacement, and
  package-manager distribution remain unavailable; this is a manual-update
  release.
- Context indexing is explicit and local; it does not watch files or rebuild
  automatically.
- MCP is read-only and stdio-only; remote MCP transport is unavailable.
- The optional model-backed D2 harness was skipped and is not required for this
  release.
- Remote catalogs, marketplace installation, automatic dependency resolution,
  skill-resource execution, and automatic backup cleanup are not included.
