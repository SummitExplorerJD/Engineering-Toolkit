# Engineering Toolkit `v0.2.2`

**Status:** Published on 2026-10-23.

`v0.2.2` introduces selective and transactional synchronization of canonical
skills for Codex, Claude Code, and OpenCode. Provider outputs remain derived,
explicitly approved, and bound to file-level ownership evidence.

## Added

- Deterministic `skills plan-sync` and `skills plan-unsync` operations for one
  explicitly selected canonical skill and provider.
- Transactional `skills sync`, `skills unsync`, and `skills recover-sync`
  commands with exact approval binding.
- Provider-appropriate `SKILL.md` rendering for Codex, Claude Code, and
  OpenCode.
- Durable plans, JSONL journals, checkpoints, retained backups, dual locking,
  ownership-last publication, and explicit recovery.
- A canonical mutation interlock while provider-owned outputs remain active.
- Offline conformance coverage for the built-in `project-guide@0.1.0` pilot.
- Portable evidence comparison across all six supported release targets.

## Safety and ownership

- Canonical skill packages remain the source of truth; derived output is never
  adopted as canonical automatically.
- Codex receives an owned `SKILL.md` sidecar without transferring ownership of
  canonical files. Claude Code and OpenCode receive isolated derived packages.
- Existing provider-native files and official Spec Kit packages remain outside
  Engineering Toolkit ownership and are preserved.
- Unowned or changed output, stale approval, collisions, linked paths,
  malformed ownership evidence, and ambiguous recovery fail closed.
- Synchronization invokes no provider runtime, executes no skill resource,
  accesses no credential, and contacts no network.
- Unsynchronization removes only files proven to be owned by the exact
  synchronization record.

## Compatibility and upgrade notes

- Existing `v0.2.1` installations can upgrade with `install.ps1` or
  `install.sh` using explicit upgrade mode.
- Provider synchronization operates on one selected canonical skill and
  provider per transaction.
- Scripts, permission requests, unresolved dependencies, unsupported
  capabilities, and lossy mappings remain non-executable.
- Provider synchronization contracts remain experimental `v1alpha1`
  interfaces.
- The source and release toolchain require Go 1.27.3, and release binaries are
  built with CGO disabled.

## Known limitations

- Native Codex, Claude Code, and OpenCode discovery remains a separately gated
  D2 activity and was not executed for this release.
- Windows executables are not Authenticode-signed.
- macOS executables are not signed or notarized.
- Production TUF activation, automatic updates, self-replacement, and
  package-manager distribution remain unavailable.
- Remote catalogs, marketplace installation, automatic dependency resolution,
  skill-resource execution, and automatic backup cleanup are not included.
