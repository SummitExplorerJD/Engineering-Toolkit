# Engineering Toolkit `v0.3.0`

**Status:** Published on 2026-10-27.

`v0.3.0` adds a safe operational front door, unified initialization, a bounded
read-only MCP interface, optional local profile advice, and two additional
first-party Go profiles. Filesystem artifacts, explicit approval, and existing
transaction lifecycles remain authoritative.

## Added

- Read-only `doctor` diagnostics with stable findings for core, workspace, and
  optional integration scopes.
- Unified `init plan` and `init apply` commands that classify one explicit
  target and delegate to the existing workspace or composition lifecycle.
- A stdio-only MCP server exposing exactly eight bounded read-only tools over
  application-owned operations.
- Optional `advise profiles` ranking with deterministic eligibility, bounded
  fresh SQLite context, privacy filtering, and fixed-loopback Ollama access.
- First-party `go-cli@0.1.0` and `go-library@0.1.0` profiles alongside
  `go-service@0.1.0` in catalog `engineering-toolkit@0.3.0`.
- Synthetic six-platform release qualification for new command, fallback,
  refusal, catalog, and MCP paths.

## Safety and compatibility

- Local intelligence is disabled by default and cannot select a profile,
  approve a plan, execute a transaction, add an ineligible candidate, or write
  canonical advice state.
- Missing or stale context, unavailable Ollama behavior, and invalid model
  responses preserve deterministic ordering.
- The Ollama endpoint remains fixed to `http://127.0.0.1:11434`; Engineering
  Toolkit never installs, starts, pulls, updates, or silently substitutes a
  model.
- MCP opens no listening socket and exposes no mutation, recovery, approval,
  provider-runtime, model, resource, prompt, or subscription capability.
- Unified initialization introduces no new plan schema, journal, checkpoint,
  lock, staging directory, backup, or recovery command.
- SQLite remains an optional rebuildable projection; canonical filesystem
  artifacts remain the source of truth.

## Local-model observations

Synthetic smoke evidence on Windows with Ollama `0.40.4` supports only the
exact observed tag and digest tuples for `phi4-mini:latest` and `granite4:3b`.
`qwen3.5:0.8b` remains allowlisted but failed the accepted structured-response
contract, so this release makes no compatibility claim for it. Exploratory
`qwen3.5:4b` testing timed out and did not add it to the allowlist.

No real repository content was used in model prompts. Mutable model tags and
installation state are not trust roots or general compatibility guarantees.

## Upgrade notes

- Existing installations can use `install.ps1` or `install.sh` with explicit
  upgrade mode.
- Existing `engkit.config/v1alpha1` files remain valid. The optional
  `intelligence` block is backward-compatible and remains disabled unless
  explicitly enabled with provider `ollama` and one allowlisted exact tag.
- No SQLite migration is required. Existing context indexes remain rebuildable
  from canonical files.
- The source and release toolchain require Go 1.27.3. Release binaries are
  built with CGO disabled.

## Known limitations

- Windows executables are not Authenticode-signed.
- macOS executables are not signed or notarized.
- Production TUF activation, automatic updates, self-replacement, and
  package-manager distribution remain unavailable; this is a manual-update
  release.
- Local intelligence supports profile-ranking advice only and requires a
  separately managed local Ollama installation and model.
- MCP is read-only and stdio-only; provider discovery configuration remains
  manual.
- Remote catalogs, marketplace installation, automatic dependency resolution,
  skill-resource execution, and automatic backup cleanup are not included.
